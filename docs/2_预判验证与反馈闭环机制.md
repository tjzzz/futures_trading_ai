# 预判验证与反馈闭环机制

> **设计目标**：在每次宏观分析中记录预判，下次分析时自动验证预判准确性，累积统计偏差，动态调整因子权重，形成"预测→验证→学习→调整"的闭环。

---

## 一、整体架构

```
分析输出（含预判）
     │
     ▼
prediction_log.json  ←── 记录预判内容
     │
     ├── 时间流逝 ...
     │
     ▼
下次分析开始
     │
     ├─ Step 0.5: 读取 prediction_log.json
     ├─ 查询当前价格
     ├─ 验证方向 + 区间命中
     ├─ 追加验证结果
     ├─ 滚动统计（近10次 → 近20次）
     └─ 自动调整因子权重
          │
          ▼
     分析时使用调整后的权重 → 加权投票 → 输出
          │
          ▼
     新的预判 → 追加到 prediction_log.json
```

## 三、验证规则

### 3.1 方向验证

| 预判方向 | 实际价格变化 | 结果 |
|---------|-------------|------|
| 看多 ↑ | 价格上涨 | ✅ 正确 |
| 看多 ↑ | 价格持平或下跌 | ❌ 错误 |
| 看空 ↓ | 价格下跌 | ✅ 正确 |
| 看空 ↓ | 价格持平或上涨 | ❌ 错误 |
| 中性 — | 任何 | 不验证方向 |

**判断标准**：价格变化幅度 > 0.5% 才算有效方向变化，避免因噪音误判。

### 3.2 区间验证

| 条件 | 结果 |
|------|------|
| 实际价在预判的 [low, high] 范围内 | ✅ 命中 |
| 实际价超出范围但偏差 < 10% * (high-low) | ⚠️ 边缘 |
| 实际价超出范围且偏差 >= 10% * (high-low) | ❌ 偏离 |

### 3.3 验证触发条件

每次分析开始前执行。触发条件：

| 条件 | 动作 |
|------|------|
| 存在未验证的预判且距上次分析 > 60 分钟 | ✅ 全部验证 |
| 存在未验证的预判但距上次分析 < 10 分钟 | ⏳ 跳过，下次再说 |
| 上次预判已验证 | ⏭ 跳过，只需统计 |

## 四、滚动统计

### 4.1 统计窗口

| 累计预判数 | 使用窗口 |
|-----------|---------|
| < 10 条 | 全部可用数据 |
| 10 ~ 19 条 | 最近 10 次 |
| >= 20 条 | 最近 20 次 |

### 4.2 统计维度

| 维度 | 计算方式 |
|------|---------|
| 方向准确率 | 方向正确次数 / 总验证次数 |
| 区间命中率 | 区间命中次数 / 总验证次数 |
| 因子准确率 | 该因子主导时方向正确次数 / 该因子主导总次数 |
| 置信度校准 | "高"置信度时的实际准确率 vs 90% 基准 |

### 4.3 统计输出摘要

```text
📊 预判偏差报告（近10次）
  方向准确率: 70% (14/20)    区间命中率: 60% (12/20)
  因子准确率:
    机会成本: 80% (8/10)    避险需求: 60% (3/5)
    货币: 50% (2/4)         持仓动量: — (0次主导)
  置信度校准:
    高置信度: 86% (6/7)     中置信度: 67% (6/9)
```

## 五、因子权重自动调整

### 5.1 调整规则

```
for each factor:
    accuracy = 该因子主导时的方向准确率（近N次）
    
    if accuracy >= 80%:
        weight ×= 1.10    # 奖励 —— 但不超过上限
    elif accuracy >= 60%:
        weight ×= 1.00    # 保持
    elif accuracy >= 40%:
        weight ×= 0.90    # 轻度惩罚
    else:
        weight ×= 0.75    # 严重惩罚

    权重下限: 0.10  （不允许完全归零）
    权重上限: 原值 × 1.5（防止单一因子过度主导）
```

### 5.2 调整时机

| 时机 | 动作 |
|------|------|
| 每完成一次验证 | 更新滚动统计，重新计算所有权重 |
| 因子从未主导过（无准确率数据） | 保持默认权重不变 |
| 某因子被惩罚到接近下限但市场 regime 切换了 | 当该因子准确率回升后，权重自动恢复 |

### 5.3 初始默认权重

| 因子 | 权重 | 说明 |
|------|------|------|
| 机会成本 | 1.0 | 常态主导因子，解释力 50-60% |
| 避险需求 | 0.8 | 中等重要性 |
| 货币 | 0.6 | 与机会成本有重叠 |
| 通胀预期 | 0.6 | 与机会成本有重叠 |
| 持仓动量 | 0.5 | 放大器角色 |
| 结构性需求 | 0.4 | 长期因素，短期变化小 |
| 银价专用 | 0.3 | 辅助因子 |

## 六、SOP 集成

在标准分析流程的 Step 1 前插入新的子步骤 `step_prep_verify`：

```
Step 0: 数据准备
├── step_prep_freshness     → 数据新鲜度判断（已有）
├── step_prep_context       → 上下文加载（已有）
├── step_prep_data          → 数据就绪检查（已有）
└── step_prep_verify   ← 【新增】→ 预判验证与权重调整
     ├── 读 prediction_log.json
     ├── 执行未验证预判的验证
     ├── 追加验证结果
     ├── 计算滚动统计
     └── 调整因子权重
```

## 七、工具链

| 工具 | 作用 | 调用方式 |
|------|------|---------|
| `tools/verify_predictions.py` | 验证 + 统计 + 权重调整 | 每次分析前由 Agent 调用 |
| `tools/analyze_macro.py` | 宏观综合研判（已修改支持动态权重） | 读取更新后的权重 |

---

## 八、使用流程（Agent 视角）

```
1. 用户说"分析一下"
2. Agent 先运行 verify_predictions.py
   → 输出预判偏差报告
   → 自动调整因子权重
3. Agent 运行 analyze_macro.py（使用调整后的权重）
   → 得到综合信号
4. Agent 按 SOP 完成分析 + 输出
5. 分析完成后，Agent 追加新的预判记录到 prediction_log.json
```

## 九、注意事项

1. **冷启动**：刚开始没有历史数据时，使用默认权重，不进行验证
2. **数据缺失**：如果黄金/白银当前价格无法获取，跳过验证，保留预判状态为未验证
3. **极端行情**：日内波动 > 5% 时，区间验证放宽至偏差 < 20%
4. **权重持久化**：权重存储在 `prediction_log.json` 中，重启不丢失
5. **可追溯**：每次权重调整记录在 `factor_weights` 的 `adjustment_log` 字段中
