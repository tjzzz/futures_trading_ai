# V1 后端 AI 引擎设计

> 核心分析引擎：Agent + 因子数据 + 知识框架。
> 实现 agent 请严格遵循本规范的接口定义和流程。

---

## 一、架构概览

```
┌──────────────────────────────────────────────────────────┐
│  触发入口                                                  │
│  Claude 对话 / 飞书消息 / 定时任务 / Web 请求               │
└──────────────────────┬───────────────────────────────────┘
                       │
┌──────────────────────▼───────────────────────────────────┐
│  Agent 推理流程                                           │
│                                                          │
│  1. 加载上下文                                            │
│     ├── user_profile.md    ← 用户画像                     │
│     ├── positions.md       ← 当前持仓                     │
│     ├── macro_memo.md      ← 上次宏观判断                  │
│     └── 框架文档            ← 1_宏观三维七因子归因框架.md     │
│                                                          │
│  2. 获取因子数据                                          │
│     └── compute_factors.py → current_factors.json        │
│                                                          │
│  3. 调用分析脚本 (可选)                                    │
│     ├── analyze_macro.py   ← 宏观综合研判                  │
│     └── analyze_position.py ← 品种归因                    │
│                                                          │
│  4. 输出分析                                              │
│     ├── 自然语言回答                                       │
│     └── 更新 macro_memo.md                                │
│                                                          │
└──────────────────────────────────────────────────────────┘
```

### 关键设计原则

1. **分析框架不硬编码** — Agent 启动时读取 `1_宏观三维七因子归因框架.md` 作为分析框架知识
2. **数据脚本只做数据，不做判断** — `compute_factors.py` 整理因子数据，方向判断由 Agent 完成
3. **分析脚本可复用** — 重复性分析写成可调用脚本，Agent 按需调用
4. **记忆驱动** — 每次分析写入 `macro_memo.md`，下次分析时加载作为起点

## 二、Agent System Prompt 设计

### 2.1 内容组织原则

System prompt 中**不包含**分析框架的具体内容（因子逻辑、指标解读等）。这些由 Agent 启动时从外部文档加载。

System prompt 只包含：
- 身份定位（分析师角色）
- 工具接口说明（哪些脚本可用、怎么调用）
- 记忆读写规则（什么时候读/写哪些文件）
- 输出规范（格式、语言风格）

### 2.2 核心指令（Prompt 片段）

```
## 知识框架

每次分析前，读取 1_宏观三维七因子归因框架.md，理解当前使用的分析框架。该文档定义了：
- 金银价格七因子归因模型
- 各因子的指标和量化方式
- 因子间关系和主导权切换逻辑
- 短期异动归因优先级

## 数据分析

调用 compute_factors.py 获取当前因子数据。输出为结构化 JSON，按七因子组织。
数据已包含行情、变化、趋势、分位数等计算值，无需重复计算。

## 分析流程

1. 读取框架文档 → 确认当前适用的分析逻辑
2. 获取因子数据 → 了解市场状态
3. 对比 macro_memo → 判断与上次分析的差异和变化
4. 综合判断 → 多空方向 + 置信度 + 主导因子 + 风险提示
5. 输出 → 结构化分析 + 自然语言回答
6. 更新 macro_memo → 写入本次判断

## 记忆规则

- 每次对话开始：读取 user_profile + positions + macro_memo
- 每次宏观分析完成：更新 macro_memo.md
- 每次交易操作后：更新 positions.md + 追加 trade_history.md
- 每次复盘后：写入 decisions.md
```

## 三、compute_factors.py 调用规范

### 3.1 被 Agent 调用方式

Agent 通过 Bash 工具调用：

```bash
python /path/to/futures_trading_ai/tools/compute_factors.py --pretty
```

输出为 stdout JSON（见数据中台设计文档），Agent 解析使用。

### 3.2 数据消费规则

Agent 拿到因子数据后：
1. 对照框架文档，理解每个因子当前数据含义
2. 检查 short/mid/long 三周期信号是否一致
3. 判断当前哪个因子占主导（参考「因子主导权切换」逻辑）
4. 综合合成方向判断

## 四、分析脚本

### 4.1 analyze_macro.py

**定位**：宏观综合研判脚本。对七个因子做信号合成，输出结构化分析结果。
**非必需**：Agent 可以不调用此脚本直接分析，但调用可提高判断一致性。

#### 接口

```bash
python tools/analyze_macro.py                           # 默认：基于当前数据
python tools/analyze_macro.py --input factors.json      # 指定输入
python tools/analyze_macro.py --output analysis.json    # 输出到文件
```

#### 输入

- `current_factors.json`（来自 compute_factors.py）
- 可选：`macro_memo.md`（上次判断，用于对比变化）

#### 输出格式

```json
{
  "timestamp": "2026-06-08 10:30:00",
  "overall": {
    "direction": "bullish",
    "confidence": 0.7,
    "label": "看多",
    "dominant_factor": "opportunity_cost"
  },
  "factors": [
    {
      "id": "opportunity_cost",
      "label": "机会成本",
      "signal": "bullish",
      "strength": 0.8,
      "evidence": "TIPS 持续下行至2.1%，日跌2bp，20日趋势 down。降息周期末期，机会成本持续下降。",
      "key_metrics": {
        "tips_10y": 2.1,
        "tips_change_d": -2,
        "nominal_10y": 4.57
      }
    },
    {
      "id": "currency",
      "label": "货币",
      "signal": "neutral",
      "strength": 0.0,
      "evidence": "DXY 99.2, 当前平稳。且 DXY 变动与 TIPS 同步，独立贡献不显著。"
    }
  ],
  "key_levels": {
    "gold_support": 4400,
    "gold_resistance": 4600,
    "silver_support": 72,
    "silver_resistance": 78
  },
  "risks": [
    {"factor": "safe_haven", "scenario": "非农数据超预期引发VIX跳升", "impact": "短期回调"},
    {"factor": "positioning", "scenario": "COT净多头接近90%分位，拥挤", "impact": "回调风险高"}
  ],
  "change_from_last": {
    "status": "changed",
    "last_timestamp": "2026-06-07 10:00:00",
    "diff": "DXY 走弱，黄金判断从偏多上调为看多",
    "trigger": "美元指数跌破100"
  }
}
```

#### 信号合成规则

```
综合方向 = 加权投票制
  每个因子: signal ∈ {bullish, bearish, neutral}
  每个因子: strength ∈ [0, 1]
  
  bullish_score = Σ(strength_i) for factor_i.signal == bullish
  bearish_score = Σ(strength_i) for factor_i.signal == bearish
  
  if bullish_score > bearish_score * 1.5 → bullish
  if bearish_score > bullish_score * 1.5 → bearish
  else → neutral/mixed

  主导因子 = factor with max(strength) among non-neutral factors
```

### 4.2 analyze_position.py

**定位**：针对某个持仓品种的归因分析。

#### 接口

```bash
python tools/analyze_position.py --symbol shfe_gold    # 沪金归因
python tools/analyze_position.py --symbol all           # 全部持仓
```

#### 输出示例

```json
{
  "symbol": "shfe_gold",
  "price": 974.02,
  "daily_change_pct": -0.15,
  "position": { "direction": "long", "lots": 2, "cost": 482.5 },
  "pnl": { "floating_pct": 1.8, "floating_abs": 3600 },

    "primary_driver": "opportunity_cost",
    "secondary_driver": "safe_haven",

    "current_stop_distance": 0.8,

```

### 4.3 generate_brief.py

**定位**：生成结构化晨报/复盘内容（可选，Agent 也可直接生成文本）。

#### 接口

```bash
python tools/generate_brief.py morning    # 生成晨报卡片内容

```

#### 输出

结构化的 Markdown / JSON，供飞书或 Web 渲染。

## 五、记忆系统交互

### 5.1 macro_memo.md 更新规范

每次宏观分析完成后写入。文件格式：

```markdown
---
tags: [trading, memory, macro]
updated: 2026-06-08 10:30
---

# 宏观备忘录

## 当前判断
- **方向**: 看多（偏多→看多，上调）
- **置信度**: 70%
- **主导因子**: 机会成本
- **触发因素**: DXY 跌破100

## 关键点位
| 品种 | 支撑 | 阻力 | 趋势 |
|------|------|------|------|
| 黄金 | 4400 | 4600 | ↑ |
| 白银 | 72 | 78 | ↑ |
| DXY | 98 | 101 | ↓ |

## 因子信号
- 机会成本: 看多(0.8) ← TIPS 持续下行
- 货币: 中性 ← DXY 平稳
- 避险: 略偏多(0.3) ← VIX 17.4 中等
- ...

## 关注焦点
- 本周 CPI 数据（预期影响：中等）
- FOMC 点阵图（月底）

## 风险提示
1. COT 净多头拥挤度偏高
2. 非农超预期可能引发回调
```

### 5.2 更新触发条件

| 场景 | 更新文件 | 更新内容 |
|------|----------|----------|
| 宏观分析完成 | `macro_memo.md` | 判断方向、置信度、关键点位、焦点、风险 |
| 开仓/平仓 | `positions.md` + `trade_history.md` | 持仓变动 + 交易记录 |
| 每日复盘完成 | `decisions.md` | 决策判断、经验总结 |

### 5.3 文件路径（常量）

```
AGENT_MEMORY   = zzzheng.AI/agents/trade-macro/workspace/memory/
VAULT_TRADE    = wiki_trade/
FRAMEWORK_DOC  = Projects/交易Agent系统/1_宏观三维七因子归因框架.md
```

## 六、输出规范

### 6.1 分析回答格式

Agent 向用户输出分析时，建议采用一致的结构：

```
📊 宏观分析 | YYYY-MM-DD HH:mm

## 综合判断
看多 ↑ | 置信度 70% | 主导因子: 机会成本

## 各因子信号
| 因子 | 信号 | 强度 | 要点 |
|------|------|------|------|
| 机会成本 | ↑ | 0.8 | TIPS 下行至 2.1% |
| 货币 | - | 0.0 | DXY 平稳 |
| 避险 | ↑ | 0.3 | VIX 17.4 中等 |
| ... | ... | ... | ... |

## 关键位置
黄金: 支撑 4400 / 阻力 4600
白银: 支撑 72 / 阻力 78

## 风险提示
⚠️ COT 净多头拥挤度偏高

## 与上次对比
上次判断: 偏多 → 本次: 看多（上调）
触发: DXY 跌破 100
```

### 6.2 符号约定

| 符号 | 含义 |
|------|------|
| ↑ | 看多 |
| ↓ | 看空 |
| - | 中性 |
| ↑↓ | 多空交织 |
| ⚠️ | 风险提示 |
| 💡 | 经验/洞察 |
| ✅ | 判断正确 |
| ❌ | 判断错误 |

## 七、定时任务

### 7.1 开盘前晨报

```bash
# 1. 获取最新因子数据
python /path/to/tools/compute_factors.py

# 2. Agent 生成晨报（通过飞书定时触发 Chat API）
#   - 读取 positions + macro_memo
#   - 调用 analyze_macro.py（可选）
#   - 输出晨报卡片
```

### 7.2 收盘后复盘

用户主动说"复盘"，Agent 按 [[wiki_trade/templates/daily_review]] 流程执行。

### 7.3 数据更新

```
cron:
  */5 * * * *  →  compute_factors.py（数据刷新）
  30 8 * * *   →  晨报触发（预留）
```
