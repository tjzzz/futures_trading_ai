## 一、采集器架构总览

所有采集器统一继承 `BaseCollector`，遵循 **fetch → parse → write** 三阶段流水线：

```
fetch()                  parse()                   写入
  │                        │                         │
  │  从外部 API/CSV/HTML    │  解析为统一格式            │  write_snapshot()
  │  拉取原始数据            │  {snapshot_key,          │  → dashboard_data.json
  │                        │    snapshot_value,       │
  ▼                        │    history_row,          │  write_history_csv()
┌──────┐                   │    grain}                │  → data/history/xxx.csv
│ HTTP │                   │                          │
│ RSS  │──────────────────►│                          ▼
│ CSV  │                   │                    ┌──────────┐
└──────┘                   │                    │  持久化   │
                           │                    └──────────┘
```

### 指标配置统一管理

指标定义不写在采集器代码里，而是集中在 `config/indicator_source.json`，通过 `IndicatorLoader` 读取：

```python
from config import loader

# 读取指标定义（快照键、CSV 字段名、展示配置）
ind = loader.get("gold")
ind["files"]["snapshot_key"]       # → "gold_price"
ind["files"]["minutely"]["field"]  # → "gold_usd"
ind["display"]["color"]            # → "#f59e0b"

# 采集器自身的配置
loader.collectors["collectors.bullion"]["frequency_minutes"]  # → 5

# Yahoo 符号映射
loader.yahoo_to_indicator["GC=F"]  # → "gold_futures"
```

这样一来：
- **指标可配置** — 加新指标只改 JSON，不改 Python
- **展示信息统一** — 前端颜色、图标、分组、单位全在 JSON 里
- **文件名解耦** — CSV 文件路径由 JSON 定义，代码不硬编码

## 二、BaseCollector 核心方法

| 方法 | 必须重写 | 返回值 | 说明 |
|------|---------|--------|------|
| `fetch()` | **是** | 原始数据（任意格式） | 从外部数据源拉取，含重试逻辑 |
| `parse(raw)` | **是** | dict（见下文格式） | 解析为结构化数据 |
| `run()` | 可选 | bool | 默认实现含完整流程，特殊场景可覆盖 |

### parse() 返回值格式

```python
{
    # ── 方案A：单字段快照（最常见）──
    "snapshot_key": "dxy",              # dashboard_data.json 中的字段名
    "snapshot_value": {                 # 字段值（可以是 dict 或 标量）
        "value": 99.148,
        "change": -0.179,
        "source": "yahoo_finance",
        "updated_at": "2026-05-21 00:45:39",
        "freshness": "实时",
    },

    # ── 方案B：多字段快照（需写入多个 dashboard 字段时）──
    "extra_snapshots": [                # 额外的字段，每项 (key, value)
        ("silver_price", {"value": 74.22, ...}),
        ("gold_silver_ratio", {"value": 60.56, ...}),
    ],

    # ── 历史行数据（写入 CSV）──
    "history_row": {                    # 键 = CSV 列名
        "dxy": 99.148,
        "us10y": 4.591,
        "vix": 17.87,
    },

    # ── 粒度（决定写入哪个 CSV 目录）──
    "grain": "minutely",                # "minutely" → data/history/minutely/
                                        # "daily"    → data/history/daily/
}
```

### write_snapshot vs 直接写快照

`BaseCollector.run()` 默认走 `write_snapshot()`（带文件锁），但**高频采集器（每5分钟）建议覆盖 `run()` 直接读写文件**，避免锁争用：

| 方式 | 适用场景 | 优点 | 缺点 |
|------|---------|------|------|
| `write_snapshot()` | 低频（日级/小时级） | 防并发脏写 | 有锁等待 |
| 直接读写文件 | 高频（分钟级） | 无锁争用，性能好 | 需自行处理并发 |

示例：[macro.py:MacroMarket.run()](../collectors/macro.py)

## 三、新增采集器步骤

### Step 1: 在 `collectors/` 下新建文件

当前采集器清单（按数据域命名）：

```
collectors/
├── base_collector.py       # 基类（无需修改）
├── bullion.py              # 金银现货 + 日线 OHLC
├── macro.py                # 宏观市场 + 日频基本面（含子命令）
├── china_futures.py        # 国内期货主力合约
├── news_rss.py             # RSS 新闻
├── backfill.py             # 历史回填
├── aggregate.py            # 分钟→日聚合
└── cleanup.py              # 数据清理
```

> **命名原则**：所有采集器按**数据域**命名（采集什么数据），而不是按数据源或频率。
> 如果同一数据域的指标过多（>10 个），可将该域展开为目录，如 `macro/market.py` + `macro/rates.py`。

线程框架：

```python
#!/usr/bin/env python3
"""
{采集器名} — {简要描述}
- 源：{数据源 URL/名称}
- 粒度：{采集频率}
- 写入：{写入的目标字段/文件}

指标定义见 config/indicator_source.json。
"""

import requests
from collectors.base_collector import BaseCollector
from config import loader


class YourNewCollector(BaseCollector):
    """{采集器说明}"""

    def __init__(self):
        super().__init__("your_source_id")

    def fetch(self):
        """从数据源获取原始数据"""
        resp = requests.get(
            "https://api.example.com/data",
            timeout=15,
            headers={"User-Agent": "Mozilla/5.0"},
        )
        resp.raise_for_status()
        return resp.json()

    def parse(self, raw):
        """从 loader 读取指标定义"""
        ind = loader.get("your_indicator_id")
        value = raw.get("price", 0)

        return {
            "snapshot_key": ind["files"]["snapshot_key"],
            "snapshot_value": {
                "value": round(value, 2),
                "source": "your_source",
                "updated_at": self._now(),
                "freshness": "实时",
            },
            "history_row": {
                "value": value,
            },
            "grain": "minutely",  # 或 "daily"
        }


if __name__ == "__main__":
    collector = YourNewCollector()
    collector.run()
```

### Step 2: 实现 `fetch()` — 数据源交互

注意事项：

- **超时**：始终设 `timeout`，建议 15s
- **User-Agent**：部分 API 需要模拟浏览器
- **重试**：高频采集器建议加重试（参考 `bullion.py:BullionSpot.fetch()`）
- **错误处理**：HTTP 错误 / JSON 解析失败 / 网络超时分别处理
- **返回格式**：返回 Python 对象（dict/list/str），不做格式转换

### Step 3: 实现 `parse()` — 数据解析

返回格式见 [第二节 parse() 返回值格式](#parse-返回值格式)。

优先从 `loader` 读取字段名，不要硬编码：

```python
# ✅ 正确：从 loader 读取
ind = loader.get("your_indicator_id")
snapshot_key = ind["files"]["snapshot_key"]          # → "your_field"
history_field = ind["files"]["daily"]["field"]       # → "your_value"

# ❌ 错误：硬编码
snapshot_key = "your_field"
history_field = "your_value"
```

freshness 标签规范：

| 标签 | 含义 | 适用 |
|------|------|------|
| `"实时"` | 延迟 < 30min | Yahoo Finance, gold-api |
| `"前一交易日"` | 延迟 1 天 | CBOE VIX 收盘 |
| `"延迟1天"` | 官方 T+1 | FRED SP500 |
| `"延迟2天"` | 官方 T+2 | FRED TIPS |
| `"延迟1~5天"` | 不定延迟 | FRED DXY |
| `"昨日数据"` | 隔日更新 | U.S. Treasury |

### Step 4: 注册指标 → `config/indicator_source.json`

新增指标需要做 3 件事：

**4a. 在 `indicators` 段定义指标：**

```json
{
  "your_indicator": {
    "name": "指标中文名",
    "name_en": "English Name",
    "category": "macro",
    "quadrant": ["green"],
    "yahoo_symbol": null,
    "collectors": ["collectors.your_new_collector"],
    "files": {
      "snapshot_key": "your_field",
      "daily": { "file": "your_data.csv", "field": "value" }
    },
    "display": {
      "icon": "Y",
      "color": "#3b82f6",
      "group": 3,
      "unit": "",
      "precision": 2
    },
    "thresholds": null
  }
}
```

关键字段说明：

| 字段 | 说明 | 示例 |
|------|------|------|
| `category` | 大类，用于前端分类 | `macro`, `precious_metal`, `sentiment`, `derived` |
| `quadrant` | 所属四象限（宏观分析用） | `green`, `blue`, `orange`, `red` |
| `yahoo_symbol` | Yahoo Finance 符号（仅 Yahoo 源需要） | `"GC=F"`, `"DX-Y.NYB"` |
| `collectors` | 处理该指标的采集器列表 | `["collectors.macro"]` |
| `files.snapshot_key` | `dashboard_data.json` 中的字段名 | `"gold_price"` |
| `files.minutely/daily` | CSV 文件和列名定义 | `{"file": "xxx.csv", "field": "xxx"}` |
| `display` | 前端展示配置（颜色、图标、单位、精度） | |
| `thresholds` | 事件监控阈值 | `{"warning": 20, "critical": 25}` |

**4b. 在 `collectors` 段注册采集器：**

```json
{
  "collectors.your_new_collector": {
    "name": "采集器中文名",
    "module": "collectors.your_new_collector",
    "frequency_minutes": 1440,
    "data_source": "your-source-id",
    "indicators": ["your_indicator"],
    "output": { ... }
  }
}
```

**4c. 在 `sources` 段注册数据源（仅全新数据源需要）：**

```json
{
  "id": "your-source-id",
  "name": "数据源中文名",
  "type": "api",
  "url": "https://api.example.com",
  "status": "active",
  "notes": "免费/付费，是否需要 Key"
}
```

如果数据源已经存在（如 `yahoo-finance`、`fred`），跳过此步。

### Step 5: 注册到调度脚本

**日频/低频采集器** → 加到 `run_all_collectors.sh` 的 `--daily` 分支：

```bash

```

**高频采集器** → 加到 `run_all_collectors.sh` 的 `--realtime` 分支。

**启动时自动运行** → 加到 `start_all.sh`。

### Step 6: 更新数据地图 `docs/02_数据中台.md`

3 处需要同步：

1. **一、数据源总览** — 新增行到数据源表格
2. **四、dashboard_data.json 字段说明** — 如果新增了快照字段
3. **五、采集器清单** — 新增行到采集器表格

### Step 7（可选）: 注册 URL 路由

如果新增了**前端页面**来展示数据，按 `docs/04_Dashboard开发.md` 流程操作。

## 四、历史数据 CSV 规范

### 目录规则

```
data/history/
├── minutely/          ← grain="minutely"
│   ├── gold_silver_minutely.csv       # 金银现货 (bullion)
│   ├── yahoo_finance_minutely.csv     # 宏观市场 (macro)
│   └── unified_gold_silver_volume.csv # 金银统一格式 (macro)
│
└── daily/             ← grain="daily"
    ├── treasury.csv       # 美债收益率
    ├── tips.csv           # TIPS 实际利率
    ├── dxy.csv            # 美元指数 (FRED)
    ├── sp500.csv          # 标普500
    ├── vix.csv            # VIX 收盘
    ├── gold_silver_daily.csv   # 金银日线 OHLC
    └── china_futures.csv       # 国内期货主力合约
```

### CSV 格式规则

| 粒度 | 首列 | 后续列 | 保留策略 |
|------|------|--------|---------|
| `minutely` | `timestamp` (YYYY-MM-DD HH:MM:SS) | 指标值列 | 保留7天，由 `cleanup.py` 清理 |
| `daily` | `date` (YYYY-MM-DD) | 指标值列 | 永久保留 |

`BaseCollector.run()` 会自动根据 `grain` 决定目录和首列，无需手动处理。

## 五、多子命令采集器

当同一数据域有不同来源/频率的指标时，可以在一个文件内通过**子命令**区分：

```bash
python -m collectors.macro market      # 实时市场 (Yahoo Finance, 5min)
python -m collectors.macro daily       # 日频基本面 (Treasury/FRED/CBOE)
python -m collectors.macro all         # 全部

python -m collectors.bullion spot      # 金银现货 (gold-api, 5min)
python -m collectors.bullion daily     # 金银日线 (Yahoo, 每天)
```

实现方式：在文件末尾用 `argparse` 解析第一个参数作为子命令：

```python
def main():
    import argparse
    parser = argparse.ArgumentParser()
    parser.add_argument("mode", nargs="?", default="spot",
                        choices=["spot", "daily"])
    args = parser.parse_args()
    if args.mode == "spot":
        BullionSpot().run()
    elif args.mode == "daily":
        run_daily()

if __name__ == "__main__":
    main()
```

### 何时应该合并，何时应该分开

| 场景 | 建议 | 示例 |
|------|------|------|
| 同一数据域，< 10 个指标，同频 | 合并一个文件 | `macro.py` (macro market + daily) |
| 同一数据域，> 10 个指标或来源不同 | 展开为目录 | 未来 `macro/market.py` + `macro/rates.py` |
| 不同数据域 | 分开放 | `bullion.py` 和 `china_futures.py` 放不同文件 |
