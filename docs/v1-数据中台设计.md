# V1 数据中台设计

> 基于金银驱动因子体系的因子对齐数据模型。
> 覆盖：数据采集 → 存储 → 查询全链路。

---

## 一、设计原则

1. **因子对齐** — 所有数据按7因子组织，采集和分析用同一套分类
2. **兜底优先** — 主数据源为 gold-api.com / FRED / U.S. Treasury / 新浪期货 等免费公开源，无单一源依赖
3. **干净分离** — `futures_trading_ai/` 是纯工程代码，不掺杂配置/个人信息
4. **统一入口** — 所有分析脚本通过 `data_query.py` 获取数据，不直接读文件

### 3.4 采集运行

```bash
# 全部运行
python -m collectors.run

# 仅实时（COMEX 金银 + spot_gold + yfinance）
python -m collectors.run realtime

# 仅日频（宏观 + 金银日频 + 新闻）
python -m collectors.run daily

# 历史回填
python -m collectors.run backfill
```

`collectors/run.py` 按优先级执行所有采集器，每采集器独立 try/except，失败不影响其他。

## 四、因子对齐数据模型

### 4.1 输出位置

```
data/factors/current_factors.json
```

### 4.2 顶层结构

```json
{
  "updated_at": "2026-06-08 10:30:00",
  "data_source": "V1 数据中台 (collectors.run 全量采集)",
  "factors": {
    "opportunity_cost": { "label": "机会成本", "signal": null, "data": {} },
    "currency": { "label": "货币", "signal": null, "data": {} },
    "safe_haven": { "label": "避险需求", "signal": null, "data": {} },
    "inflation": { "label": "通胀预期", "signal": null, "data": {} },
    "positioning": { "label": "持仓动量", "signal": null, "data": {} },
    "structural_demand": { "label": "结构性需求", "signal": null, "data": {} },
    "silver_specific": { "label": "银价专用", "signal": null, "data": {} }
  },
  "events": [],
  "summary": {}
}
```

### 4.3 各因子数据字段

#### 因子1：机会成本 (opportunity_cost)

| 字段 | 类型 | 来源 | 频率 | 说明 |
|------|------|------|------|------|
| `tips_10y` | float | `macro_tips` (FRED) | 日频 | 实际利率，核心 |
| `tips_10y_change_d` | float | 计算 | 日频 | TIPS 日变化 (bp) |
| `tips_10y_trend_20d` | str | 计算 | 日频 | `up`/`down`/`flat` |
| `nominal_10y` | float | `treasury` (U.S. Treasury) | 日频 | 10Y 名义收益率 |
| `nominal_10y_change_d` | float | 计算 | 日频 | 10Y 日变化 (bp) |
| `fedwatch_dots` | dict | 手动/FOMC会后 | FOMC会后 | 利率点阵图 |
| `fedwatch_prob` | dict | `yfinance` FF=F | 实时 | 联邦基金期货隐含概率 |

**备注**：nominal_10y 来自 U.S. Treasury 收益率曲线（`treasury`），非 AKShare/东方财富。

#### 因子2：货币 (currency)

| 字段 | 类型 | 来源 | 频率 | 说明 |
|------|------|------|------|------|
| `dxy` | float | `macro_index` (FRED) | 日频 | 美元指数 |
| `dxy_change_d` | float | 计算 | 日频 | DXY 日变化 |
| `dxy_vs_200ma` | str | 计算 | 日频 | `above`/`below`/`at` |
| `dxy_trend_60d` | str | 计算 | 日频 | `up`/`down`/`flat` |

**DXY 说明**：FRED DTWEXBGS（日频），数据延迟 T+2~4，无实时数据。实时参考可由 `yfinance` 补充但不作为因子信号依据。

**DXY 正交化说明**：DXY 约50%解释力与 TIPS 重叠。因子信号计算时：
- 先检查 TIPS 是否同步变动
- 若同向 → 归入机会成本，货币因子信号置为 `neutral`
- 若 DXY 独立异动 → 货币因子信号生效

#### 因子3：避险需求 (safe_haven)

| 字段 | 类型 | 来源 | 频率 | 说明 |
|------|------|------|------|------|
| `vix` | float | `vix` (CBOE) | 日频 | VIX 恐慌指数 |
| `vix_change_d` | float | 计算 | 日频 | |
| `vix_ma20` | float | 计算 | 日频 | VIX 20日均值 |
| `vix_regime` | str | 计算 | 日频 | `calm`(<15) / `moderate`(15-25) / `panic`(>25) / `crisis`(>30+利差飙升) |
| `sp500` | float | `macro_index` (FRED) | 日频 | |
| `sp500_change_d` | float | 计算 | 日频 | |
| `credit_spread` | dict | `macro_tips` (FRED HY 利差) | 日频 | HYG-LQD 利差 |

**备注**：VIX 和 SP500 来自 FRED/CBOE 日频，无实时数据。

**流动性危机判定**：
```
crisis_flag = vix > 30 AND credit_spread > 500bp
→ 黄金短期偏空（抛售变现），非避险买入
```

#### 因子4：通胀预期 (inflation)

| 字段 | 类型 | 来源 | 频率 | 说明 |
|------|------|------|------|------|
| `breakeven_10y` | float | 计算 (10Y - TIPS) | 日频 | 盈亏平衡通胀率 |
| `breakeven_change_d` | float | 计算 | 日频 | |
| `cpi_mom` | float | `macro_tips` (FRED) | 月度 | |
| `cpi_yoy` | float | `macro_tips` (FRED) | 月度 | |
| `pce_core` | float | `macro_tips` (FRED) | 月度 | 核心 PCE |
| `oil_wti` | float | `macro_index` (FRED) | 日频 | 原油→通胀预期传导 |
| `oil_brent` | float | `macro_index` (FRED) | 日频 | |

#### 因子5：持仓动量 (positioning)

| 字段 | 类型 | 来源 | 频率 | 说明 |
|------|------|------|------|------|
| `gold_futures_oi` | int | `futures_sina` (新浪外盘 COMEX) | 实时 | COMEX 黄金持仓量 |
| `silver_futures_oi` | int | `futures_sina` (新浪外盘 COMEX) | 实时 | COMEX 白银持仓量 |
| `gld_holdings` | float | `yfinance` GLD | 实时 | GLD ETF 价格/交易量 |
| `slv_holdings` | float | `yfinance` SLV | 实时 | SLV ETF 价格/交易量 |
| `shfe_gold_oi` | int | `futures_shfe` (新浪国内期货) | 日频 | 沪金持仓量 |
| `shfe_silver_oi` | int | `futures_shfe` (新浪国内期货) | 日频 | 沪银持仓量 |

**备注**：COMEX OI 通过 `futures_sina`（新浪外盘期货接口）实时获取。SHFE OI 通过 `futures_shfe`（新浪国内期货 `futures_main_sina`）日频获取。

**持仓量信号判定**：
```
价格↑ + OI↑ = 新多头入场，趋势确认 (看多)
价格↑ + OI↓ = 空头平仓，趋势衰竭 (警告)
价格↓ + OI↑ = 新空头入场，下跌确认 (看空)
价格↓ + OI↓ = 多头平仓，下跌衰竭 (警告)
```

#### 因子6：结构性需求 (structural_demand)

| 字段 | 类型 | 来源 | 频率 | 说明 |
|------|------|------|------|------|
| `central_bank_gold_t` | float | 手动/新闻 (`news/rss`) | 按需 | 全球央行季度购金量(吨) |
| `last_known_note` | str | 手动 | 按需 | 最近已知趋势描述 |

#### 因子7：银价专用 (silver_specific)

| 字段 | 类型 | 来源 | 频率 | 说明 |
|------|------|------|------|------|
| `gold_silver_ratio` | float | `futures_sina` (COMEX 推导) | 实时 | 金银比 |
| `gs_ratio_percentile` | float | 计算 | 日频 | 过去5年分位数 |

**备注**：金银比同时由 `futures_sina`（COMEX 期货）和 `spot_daily`（日频现货）来源可用。

**均值回归逻辑**：
```
金银比 > 90 → 白银相对低估，看多 silver
金银比 < 40 → 白银相对高估，看空 silver
```

## 五、新闻事件管道

### 5.1 采集链路

新闻数据通过 `news/` 包下三模块级联处理：

| 模块 | 功能 | 频率 |
|------|------|------|
| `news/rss.py` | 采集 CNBC / MarketWatch RSS，关键词匹配归类到七因子 | 30分钟 |
| `news/calendar.py` | 本地计算生成宏观事件日历（基于固定时间表 + 数据 Query） | 每日 |
| `news/topics.py` | 按因子维度汇聚新闻，生成事件归因摘要 | 每日 |

**新闻归因**：`config/constants.py` 中的 `QUADRANT_KEYWORDS` 定义因子关键词映射，每条新闻自动归类。

### 5.2 输出文件

```
data/events/latest_feed.json      → 最新新闻列表（RSS + 归因）
data/events/event_tracker.json    → 活跃事件 + 宏观日历
```

`event_tracker.json` 包含 `calendar_events` 字段：
```json
{
  "active_events": [...],
  "calendar_events": [
    {
      "time": "20:30",
      "region": "美国",
      "event": "CPI 同比",
      "importance": "★★★",
      "actual": "3.2%",
      "expected": "3.1%",
      "previous": "3.0%",
      "factor_tags": ["inflation"]
    }
  ],
  "source": "news/rss + news/calendar"
}
```

## 六、compute_factors.py 规范

### 6.1 定位

从 `data_query.py` 读取原始数据，按因子模型组织为结构化 JSON。**不做方向判断**，只做数据整理。

### 6.2 接口

```bash
python tools/compute_factors.py          # 全量计算，输出到 data/factors/current_factors.json
python tools/compute_factors.py --factor opportunity_cost  # 单因子
python tools/compute_factors.py --pretty  # 带格式化输出到 stdout
```

### 6.3 数据源说明

| 因子字段 | 采集器 | 数据源 | 延迟 |
|---------|--------|--------|------|
| DXY | `macro_index` | FRED DTWEXBGS | T+2~4 |
| SP500 | `macro_index` | FRED SP500 | T+2~4 |
| VIX | `vix` | CBOE CSV | T+1 |
| US 10Y / 2Y / 30Y | `treasury` | U.S. Treasury CSV | T+1 |
| TIPS 10Y | `macro_tips` | FRED DFII10 | T+2~4 |
| COMEX 金银实时 | `futures_sina` | 新浪外盘期货 | 实时 (5~30秒) |
| 金银现货日频 | `spot_daily` | Yahoo GLD/SLV | T+1 |
| CPI / PCE | `macro_tips` | FRED 月度 | 月频 |
| HY 信用利差 | `macro_tips` | FRED 信用利差 | T+2~4 |
| 原油 / 铜 | `macro_index` | FRED | T+1~3 |
| 沪金 / 沪银 | `futures_shfe` | 新浪国内期货 | T+1 |
| 新闻 | `news/rss` | CNBC / MarketWatch RSS | 实时 |
| 宏观日历 | `news/calendar` | 本地计算 | 每日 |

**compute_factors.py 读取 dashboard_data.json 时无需关心数据来源**，统一通过 snapshot_key 读取。

### 6.4 注意事项

- 所有时间字段统一为 `"YYYY-MM-DD HH:mm:ss"`，时区 CST (UTC+8)
- 缺失数据填 `null`，不填 0（避免误导）
- 数据来源标注 `source` 字段，便于排查
- 定时运行频率：建议配套 cron 5分钟一次

## 八、数据质量与维护

### 8.1 字段完整性检查

每个因子数据块必须包含：
- `label` — 中文名称
- `signal` — 初始为 null，由 AI 引擎填入
- `data` — 包含所有已配置字段（缺失填 null）
- `data.*.source` — 数据来源标注

### 8.2 数据过期标记

如果某个数据源超过正常更新间隔 2 倍仍未更新，在对应字段加标记：
```json
{
  "dxy": { "value": 99.5, "stale": true, "stale_since": "2026-06-05" }
}
```

### 8.3 采集状态监控

`data/events/monitor_state.json` 记录每个采集器最后运行时间和状态，由 `collectors/run.py` 更新。

## 九、后端频控要求

> 每个数据后端有不同的频率限制（rate limit）。超出限制会被断开连接或临时封 IP。
> `collectors/run.py` 内置后端感知频控器，通过 `BACKEND_INTERVAL` 字典配置。

### 9.1 后端最小请求间隔

| 后端 | min 间隔 | 说明 | 对应采集器 |
|------|:--------:|------|-----------|
| **新浪财经** `sina` | 0.5 秒 | 几乎无限制，秒级轮询可用 | `futures_sina`, `futures_shfe` |
| **gold-api.com** `goldapi` | 1 秒 | 宽松 | `spot_gold` |
| **Yahoo Finance** `yfinance` | **15 秒** | **严格**，频繁触发 429 | `spot_daily`, `yfinance` |
| **FRED** `fred` | 1 秒 | CSV 下载，宽松 | `macro_tips`, `macro_index` |
| **U.S. Treasury** `ustreasury` | 1 秒 | CSV 下载，宽松 | `treasury` |
| **CBOE** `cboe` | 1 秒 | CSV 下载，宽松 | `vix` |
| **ExchangeRate-API** `exchangerate` | 1 秒 | 宽松 | `macro_index` (USD/CNY) |
| **RSS Feed** `rss` | 30 秒 | 避免被 RSS 源屏蔽 | `news/rss` |
| **本地计算** `local` | 无 | 无网络请求 | `news/calendar`, `news/topics` |

### 9.2 频控设计（run.py 实际配置）

```python
# run.py 中的频控逻辑
BACKEND_INTERVAL = {
    "sina":        0.5,    # 秒
    "yfinance":    15.0,
    "rss":         30.0,
    # ...
}

# 每个采集器映射到最严格的后端
COLLECTOR_BACKEND = {
    "futures_sina":   "sina",
    "spot_daily":     "yfinance",
    "news_rss":       "rss",
    # ...
}
```

### 9.3 已知问题

| 问题 | 影响 | 状态 |
|------|------|:----:|
| **Yahoo Finance** 频繁 429 | `spot_daily` 和 `yfinance` 采集可能失败；已使用 8s symbol 间隔 + 5 次退避重试 + 新 Session | ⚠️ 偶发 |
| **CBOE VIX** 偶发 SSL 错误 | VIX 日频采集偶发失败 | ⚠️ 瞬断，重试一般成功 |

### 9.4 优化建议

1. **Yahoo 429**：`spot_daily` 已通过 6mo 范围（非 1y）+ 8s symbol 间隔 + 5 次退避重试缓解，若仍频发可考虑缓存
2. **FRED 数据延迟**：大部分 FRED 系列 T+2~4，无法实时，日频采集安排在每日 9:00 后即可

## 十、安装与部署

### 10.1 安装依赖

```bash
pip install -r requirements.txt
```

### 10.2 验证采集

```bash
# 验证单采集器
python -m collectors.futures_sina        # COMEX 金银实时
python -m collectors.spot_gold           # gold-api 现货
python -m collectors.yfinance            # Yahoo Finance
python -m collectors.spot_daily          # 金银日频
python -m collectors.treasury            # 美债

# 验证全链路
python -m collectors.run
```

### 10.3 定时任务建议

```bash
# crontab -e
* * * * * cd /path/to/futures_trading_ai && python -m collectors.run realtime   # 每分钟：实时采集
0 9 * * * cd /path/to/futures_trading_ai && python -m collectors.run daily     # 每天9点：日频采集
*/30 * * * * cd /path/to/futures_trading_ai && python -m collectors.run daily  # 每30分钟：新闻刷新
```
