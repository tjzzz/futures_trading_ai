# V1 数据中台设计

> 基于金银驱动因子体系的因子对齐数据模型。
> 覆盖：数据采集 → 存储 → 查询全链路。

---

## 一、设计原则

1. **因子对齐** — 所有数据按7因子组织，采集和分析用同一套分类
2. **AKShare 主源** — 东方财富/金十数据/华尔街见闻/新浪为主数据源，原有采集器降级为兜底
3. **干净分离** — `futures_trading_ai/` 是纯工程代码，不掺杂配置/个人信息
4. **统一入口** — 所有分析脚本通过 `data_query.py` 获取数据，不直接读文件

---

### 3.3 采集器清单

#### 主源（AKShare 系列）

| 采集器 | 数据 | 方法 | 频率 |
|--------|------|------|------|
| `akshare_futures.py` | COMEX 金银实时行情 + investing.com 日频历史 | `futures_foreign_commodity_realtime(["GC","SI"])` + `futures_foreign_hist("黄金")` | 实时 (3~30秒) / 日频历史 |
| `akshare_global.py` | DXY / SP500 / VIX | `index_global_hist_em("美元指数"/"标普500"/"VIX")` | 每日 |
| `akshare_bond.py` | 美债 2Y/10Y/30Y 收益率 + 中国国债 | `bond_zh_us_rate()` | 每日 |
| `akshare_news.py` | 金十数据实时新闻 + 华尔街见闻宏观日历 + 百度财经经济指标 | `js_news()` + `macro_info_ws()` + `news_economic_baidu()` | 新闻 5~15分钟 / 日历每日 |

#### 兜底（原有采集器）

| 采集器 | 数据 | 方法 | 频率 |
|--------|------|------|------|
| `gold_api.py` | XAU/USD 金银现货（备用验证） | gold-api.com API | 5分钟 |
| `yfinance_batch.py` | DXY / US10Y / VIX / 金银期货 / 原油 / GLD / SLV / FedWatch | Yahoo Finance v8 API + yfinance | 5分钟（兜底） |
| `treasuries.py` | 美债 2Y/10Y/30Y（验证） | U.S. Treasury CSV | 每日 |
| `fred.py` | TIPS 10Y / CPI / PCE / HY 信用利差 | FRED CSV | 每日 |
| `cboe_vix.py` | VIX 日频历史（备份） | CBOE CSV | 每日 |
| `fallback.py` | WTI / Brent / 铜 / USD/CNY | FRED + ExchangeRate-API | 每日 |
| `china_futures.py` | 沪金 / 沪银 OHLC+持仓量 | AKShare/新浪 `futures_main_sina("AU0")` | 每日 |
| `news_rss.py` | CNBC / MarketWatch 新闻（备用） | RSS Feed | 30分钟 |

### 3.4 兜底链路示例

以 DXY 为例说明兜底链路：

```
1. akshare_global (东方财富) ──── 成功 → 写入 dashboard_data.json
                                         ↓
2. 东方财富失败 → yfinance_batch (Yahoo) ─── 成功 → 写入
                                                    ↓
3. 全部失败 → 不更新，保留上次值，freshness 标记 stale
```

### 3.5 后端频控说明

每个后端数据源有不同的频率限制（rate limit）。`collectors/run.py` 内置了后端感知的频控器，按后端分组跟踪上次调用时间，自动等待最小间隔。

详细频控配置见第 九 节。

### 3.6 统一采集运行

```bash
# 全部运行（推荐 — AKShare 主源优先）
python -m collectors.run

# 仅实时（COMEX 金银 + gold-api + yfinance）
python -m collectors.run realtime

# 仅日频（AKShare 全球指数/债券/新闻 + 兜底）
python -m collectors.run daily

# 历史回填
python -m collectors.run backfill
```

`collectors/run.py` 按优先级执行所有采集器：
1. **主源先行** — AKShare 系列先执行
2. **兜底补缺** — 原有采集器在主源失败时补上
3. **容错写入** — 每采集器独立 try/except，失败不影响其他

## 四、因子对齐数据模型

### 4.1 输出位置

```
data/factors/current_factors.json
```

### 4.2 顶层结构

```json
{
  "updated_at": "2026-06-08 10:30:00",
  "data_source": "V1 采集 (AKShare 主源) + compute_factors.py",
  "factors": {
    "opportunity_cost": { "label": "机会成本", "signal": null, "data": {} },
    "currency": { "label": "货币", "signal": null, "data": {} },
    "safe_haven": { "label": "避险需求", "signal": null, "data": {} },
    "inflation": { "label": "通胀预期", "signal": null, "data": {} },
    "positioning": { "label": "持仓动量", "signal": null, "data": {} },
    "structural_demand": { "label": "结构性需求", "signal": null, "data": {} },
    "silver_specific": { "label": "银价专用", "signal": null, "data": {} }
  },
  "events": [],
  "summary": {}
}
```

### 4.3 各因子数据字段

#### 因子1：机会成本 (opportunity_cost)

| 字段 | 类型 | 来源 | 频率 | 说明 |
|------|------|------|------|------|
| `tips_10y` | float | FRED (`fred.py`) | 日频 | 实际利率，核心 |
| `tips_10y_change_d` | float | 计算 | 日频 | TIPS 日变化 (bp) |
| `tips_10y_trend_20d` | str | 计算 | 日频 | `up`/`down`/`flat` |
| `nominal_10y` | float | AKShare (`akshare_bond.py`) | 日频 | 10Y 名义收益率 |
| `nominal_10y_change_d` | float | 计算 | 日频 | 10Y 日变化 (bp) |
| `fedwatch_dots` | dict | 手动/FOMC会后 | FOMC会后 | 利率点阵图 |
| `fedwatch_prob` | dict | Yahoo FF=F (`yfinance_batch.py`) | 实时 | 联邦基金期货隐含概率 |

**数据源变化**：nominal_10y 从 yfinance 切到 AKShare/东方财富，更稳定。

#### 因子2：货币 (currency)

| 字段 | 类型 | 来源 | 频率 | 说明 |
|------|------|------|------|------|
| `dxy` | float | AKShare (`akshare_global.py`) | 日频 | 美元指数 |
| `dxy_change_d` | float | 计算 | 日频 | DXY 日变化 |
| `dxy_vs_200ma` | str | 计算 | 日频 | `above`/`below`/`at` |
| `dxy_trend_60d` | str | 计算 | 日频 | `up`/`down`/`flat` |

**数据源变化**：DXY 从 yfinance 切到 AKShare/东方财富。

**DXY 正交化说明**：DXY 约50%解释力与 TIPS 重叠。因子信号计算时：
- 先检查 TIPS 是否同步变动
- 若同向 → 归入机会成本，货币因子信号置为 `neutral`
- 若 DXY 独立异动 → 货币因子信号生效

#### 因子3：避险需求 (safe_haven)

| 字段 | 类型 | 来源 | 频率 | 说明 |
|------|------|------|------|------|
| `vix` | float | AKShare (`akshare_global.py`) / CBOE (`cboe_vix.py`) | 日频 | VIX 恐慌指数 |
| `vix_change_d` | float | 计算 | 日频 | |
| `vix_ma20` | float | 计算 | 日频 | VIX 20日均值 |
| `vix_regime` | str | 计算 | 日频 | `calm`(<15) / `moderate`(15-25) / `panic`(>25) / `crisis`(>30+利差飙升) |
| `sp500` | float | AKShare (`akshare_global.py`) | 日频 | |
| `sp500_change_d` | float | 计算 | 日频 | |
| `credit_spread` | dict | FRED (`fred.py`) | 日频 | HYG-LQD 利差 |

**数据源变化**：VIX 和 SP500 从 yfinance 切到 AKShare/东方财富。

**流动性危机判定**：
```
crisis_flag = vix > 30 AND credit_spread > 500bp
→ 黄金短期偏空（抛售变现），非避险买入
```

#### 因子4：通胀预期 (inflation)

| 字段 | 类型 | 来源 | 频率 | 说明 |
|------|------|------|------|------|
| `breakeven_10y` | float | 计算 (10Y - TIPS) | 日频 | 盈亏平衡通胀率 |
| `breakeven_change_d` | float | 计算 | 日频 | |
| `cpi_mom` | float | FRED (`fred.py`) | 月度 | |
| `cpi_yoy` | float | FRED (`fred.py`) | 月度 | |
| `pce_core` | float | FRED (`fred.py`) | 月度 | 核心 PCE |
| `oil_wti` | float | FRED (`fallback.py`) | 日频 | 原油→通胀预期传导 |
| `oil_brent` | float | FRED (`fallback.py`) | 日频 | |

#### 因子5：持仓动量 (positioning)

| 字段 | 类型 | 来源 | 频率 | 说明 |
|------|------|------|------|------|
| `gold_futures_oi` | int | AKShare (`akshare_futures.py`) | 实时 | COMEX 黄金持仓量 |
| `silver_futures_oi` | int | AKShare (`akshare_futures.py`) | 实时 | COMEX 白银持仓量 |
| `gld_holdings` | float | Yahoo (`yfinance_batch.py`) | 实时 | GLD ETF 价格/交易量 |
| `slv_holdings` | float | Yahoo (`yfinance_batch.py`) | 实时 | SLV ETF 价格/交易量 |
| `shfe_gold_oi` | int | AKShare/新浪 (`china_futures.py`) | 日频 | 沪金持仓量 |
| `shfe_silver_oi` | int | AKShare/新浪 (`china_futures.py`) | 日频 | 沪银持仓量 |

**数据源变化**：COMEX OI 现在通过 akshare_futures 实时获取，不再依赖 yfinance。

**持仓量信号判定**：
```
价格↑ + OI↑ = 新多头入场，趋势确认 (看多)
价格↑ + OI↓ = 空头平仓，趋势衰竭 (警告)
价格↓ + OI↑ = 新空头入场，下跌确认 (看空)
价格↓ + OI↓ = 多头平仓，下跌衰竭 (警告)
```

#### 因子6：结构性需求 (structural_demand)

| 字段 | 类型 | 来源 | 频率 | 说明 |
|------|------|------|------|------|
| `central_bank_gold_t` | float | 手动/新闻 (`akshare_news`) | 按需 | 全球央行季度购金量(吨) |
| `last_known_note` | str | 手动 | 按需 | 最近已知趋势描述 |

#### 因子7：银价专用 (silver_specific)

| 字段 | 类型 | 来源 | 频率 | 说明 |
|------|------|------|------|------|
| `gold_silver_ratio` | float | AKShare (`akshare_futures` COMEX推导) | 实时 | 金银比 |
| `gs_ratio_percentile` | float | 计算 | 日频 | 过去5年分位数 |

**数据源变化**：金银比由 gold-api 现货推导改为 COMEX 期货推导，趋势一致。

**均值回归逻辑**：
```
金银比 > 90 → 白银相对低估，看多 silver
金银比 < 40 → 白银相对高估，看空 silver
```

## 五、新闻事件管道

### 5.1 主源：AKShare 新闻（Phase 1）

`akshare_news.py` 三层数据源架构：

| 层 | 数据源 | 内容 | 频率 |
|---|--------|------|------|
| 新闻 | 金十数据 `js_news(indicator='最新资讯')` | 最近4小时实时财经快讯 | 5~15分钟 |
| 数据 | 金十数据 `js_news(indicator='最新数据')` | 最新经济指标实际值 | 实时 |
| 日历 | 华尔街见闻 `macro_info_ws(date)` | 结构化宏观事件日历（含预期/前值） | 每日 |
| 补充 | 百度财经 `news_economic_baidu()` | 经济指标日历（含多国） | 每日 |

**新闻归因**：复用 `news_rss.py` 的七因子关键词匹配（`FACTOR_KEYWORDS`），每条新闻自动归类。

### 5.2 兜底：RSS 新闻

`news_rss.py` 保留，当 AKShare 新闻失败时自动补缺。

### 5.3 输出文件

```
data/events/latest_feed.json      → 最新新闻列表（金十数据）
data/events/event_tracker.json    → 活跃事件 + 宏观日历
```

`event_tracker.json` 新增 `calendar_events` 字段：
```json
{
  "active_events": [...],
  "calendar_events": [
    {
      "time": "20:30",
      "region": "美国",
      "event": "CPI 同比",
      "importance": "★★★",
      "actual": "3.2%",
      "expected": "3.1%",
      "previous": "3.0%",
      "factor_tags": ["inflation"]
    }
  ],
  "source": "akshare (jin10 + wallstreetcn + baidu)"
}
```

### 5.4 与异动归因的集成

华尔街见闻日历的结构化事件可直接用于异动归因的 Step 2（事件排查）：

```
事件触发检查流程：
1. 从 event_tracker.json → calendar_events 读取今日事件
2. 对比 actual vs expected 偏差
3. 偏差 > 阈值 → 该事件是异动触发器
```

## 六、compute_factors.py 规范

### 6.1 定位

从 `data_query.py` 读取原始数据，按因子模型组织为结构化 JSON。**不做方向判断**，只做数据整理。

### 6.2 接口

```bash
python tools/compute_factors.py          # 全量计算，输出到 data/factors/current_factors.json
python tools/compute_factors.py --factor opportunity_cost  # 单因子
python tools/compute_factors.py --pretty  # 带格式化输出到 stdout
```

### 6.3 数据源更新说明

| 因子字段 | 旧源 | 新源 | 影响 |
|---------|------|------|------|
| DXY | yfinance `^DX-Y.NYB` | AKShare `index_global_hist_em("美元指数")` | 日频更稳定 |
| SP500 | yfinance `^GSPC` | AKShare `index_global_hist_em("标普500")` | 日频更稳定 |
| VIX | yfinance `^VIX` | AKShare `index_global_hist_em("VIX")` | 日频更稳定 |
| US 10Y | yfinance `^TNX` | AKShare `bond_zh_us_rate()` | 日频，含变化率 |
| COMEX金银 | yfinance `GC=F/SI=F` | AKShare `futures_foreign_commodity_realtime` | 实时且稳定 |
| 新闻 | CNBC/MarketWatch RSS | AKShare 金十数据 | 中文+实时 |

**compute_factors.py 读取 dashboard_data.json 时无需关心数据来源**，统一通过 snapshot_key 读取。

### 6.4 注意事项

- 所有时间字段统一为 `"YYYY-MM-DD HH:mm:ss"`，时区 CST (UTC+8)
- 缺失数据填 `null`，不填 0（避免误导）
- 数据来源标注 `source` 字段，便于排查
- 定时运行频率：建议配套 cron 5分钟一次

## 九、后端频控要求

> 每个数据后端有不同的频率限制（rate limit）。超出限制会被断开连接或临时封 IP。
> `collectors/run.py` 内置后端感知频控器，通过 `BACKEND_INTERVAL` 字典配置。

### 9.1 后端最小请求间隔

| 后端 | min 间隔 | 说明 | 对应采集器 |
|------|:--------:|------|-----------|
| **新浪财经** `sina` | 0.5 秒 | 几乎无限制，秒级轮询可用 | `akshare_futures`, `china_futures` |
| **东方财富** `eastmoney` | 2 秒 | 有频控但较宽松，连调会逐步变慢 | `akshare_global`, `akshare_bond` |
| **上海金属网** `shmet` | 1 秒 | 宽松 | `akshare_news` (SHMET 新闻) |
| **华尔街见闻** `wallstreetcn` | 10 分钟 | 单日调用次数有限，频繁调可能封 | `akshare_news` (宏观日历) |
| **百度财经** `baidu` | 2 分钟 | 适中 | `akshare_news` (经济日历) |
| **gold-api.com** `goldapi` | 1 秒 | 宽松，无需 API Key | `gold_spot` |
| **Yahoo Finance** `yfinance` | **15 秒** | **严格**，12 ticker 批量请求频繁触发 429 | `yfinance_batch` |
| **FRED** `fred` | 1 秒 | CSV 下载，宽松 | `fred`, `fallback` (原油/铜) |
| **U.S. Treasury** `ustreasury` | 1 秒 | CSV 下载，宽松 | `treasuries` |
| **CBOE** `cboe` | 1 秒 | CSV 下载，宽松 | `cboe_vix` |
| **ExchangeRate-API** `exchangerate` | 1 秒 | 宽松 | `fallback` (USD/CNY) |
| **RSS Feed** `rss` | 30 秒 | 避免被 RSS 源屏蔽 | `news_rss` |
| **本地计算** `local` | 无 | 无网络请求 | `news_calendar`, `news_topics` |

### 9.2 频控设计

```python
# run.py 中的频控逻辑
BACKEND_INTERVAL = {
    "sina":        0.5,    # 秒
    "eastmoney":   2.0,
    "yfinance":    15.0,
    "wallstreetcn": 600.0,  # 10分钟
    "baidu":       120.0,   # 2分钟
    # ...
}

# 每个采集器映射到最严格的后端
COLLECTOR_BACKEND = {
    "akshare_futures": "sina",
    "akshare_global":  "eastmoney",
    "akshare_news":    "baidu",   # 多后端取最严格
    # ...
}

# 执行前自动等待
def _rate_limit(backend):
    interval = BACKEND_INTERVAL[backend]
    elapsed = time.time() - last_call_time[backend]
    if elapsed < interval:
        time.sleep(interval - elapsed)
```

### 9.3 已知问题

| 问题 | 影响 | 状态 |
|------|------|:----:|
| **东方财富** `push2.eastmoney.com` 被系统代理屏蔽 | DXY/SP500/VIX 无法通过 AKShare 采集 | 🔴 需在代理中白名单 `eastmoney.com` |
| **Yahoo Finance** 频繁 429 | DXY/SP500/VIX/ETF/FedWatch 数据停滞 18 天 | 🔴 min 间隔已设为 15s，但仍常超限 |
| **investing.com** `futures_foreign_hist` API 变更 | 无法获取 COMEX 金银日频历史 | 🔴 函数已废弃，跳过不报错 |
| **CBOE VIX** 偶发 SSL 错误 | VIX 日频采集偶发失败 | ⚠️ 瞬断，重试一般成功 |

### 9.4 优化建议

1. **东方财富被代理屏蔽**：在代理客户端（Clash X / Surge / V2rayU）中将 `eastmoney.com` 加入直连/白名单
2. **yfinance 429**：降低 `yfinance_batch` 调用频率至 30 秒以上，或减少单次 ticker 数量（当前 12 个）
3. **investing.com**：考虑用新浪期货日频或 FRED 替代
4. **华尔街见闻**：每日只需调用 1-2 次，固定在 8:30 和 20:30（数据发布时段）
